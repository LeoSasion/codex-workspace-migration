# Windows 外部执行边界

在需要交付桌面快捷方式、CMD 或 PowerShell 收尾工具时读取。

## 路径身份

`Test-Path` 成功只能证明当前进程能看见该路径。打包应用可能将 AppData 逻辑路径映射到包的私有位置，普通进程看到的实体不同。

- 用当前文件句柄的最终路径（例如 Windows `GetFinalPathNameByHandleW`）识别映射；不要直接猜某个包的 `LocalCache` 路径。
- 必要时用 `GetCurrentPackageFullName` 区分打包与普通进程。由 Codex 创建子进程不必然证明其环境与桌面一致，去掉环境变量也不必然去掉包身份。
- 私有材料优先选择已验证应用内外都可见、且在迁移根之外的真实目录。例如 `%USERPROFILE%/.workspace-migration/<run-id>/` 是候选布局，仍需验证，不是对所有机器的保证。
- 凭据复制后核对字节和访问控制，保留原件。不要为解决可读性把私有目录授权给 Everyone，也不要输出凭据或完整配置。

## 实际入口的验证矩阵

在准备完成后，通过一个真实普通 Windows 进程执行最终入口的 `--check-only`。使用隐藏窗口运行后台验证；需要用户现场操作的收尾入口才保留可见窗口。没有获得普通进程证据时，明确记录该项未覆盖。

| 条件 | 应覆盖的行为 |
| --- | --- |
| PATH 只保留系统目录 | Python、Git、搜索工具、Docker 和客户端程序依然通过核验过的绝对路径定位 |
| cwd 与仓库无关 | 相对资源基于脚本自身位置或显式参数，不能依赖当前目录 |
| 目录名含中文和空格 | 结构化参数或正确 shell 引用，完整传递到最内层 |
| CMD → PowerShell → Python | 外层返回最内层真实退出码；不因最后打印提示而返回成功 |
| 应用内外分别读取 | 同一私有材料的摘要相等，而不只是两边都存在同名文件 |
| 程序安装版本变化 | 重新定位并验证当前程序；不静默选择一个历史版本 |

如果启动后台辅助进程，使用 `Start-Process -WindowStyle Hidden` 或具有同等行为的方式，不弹出用户不需要操作的窗口。不要为了获得普通环境而调整系统 PATH、执行策略、信任或全局安装。

脚本应把依赖程序解析成受约束的映射：固定安装根、唯一有效候选、正确文件类型、必要的版本／哈希检查。候选有多个时按当前安装元数据判断；没有可靠元数据就停止，不按目录排序猜“最新版”。

## 编码与错误

- Python 文本读写明确 `encoding='utf-8'`；调用未明确编码的工具时可使用进程级 `python -X utf8`。避免为一个任务修改系统代码页或全局环境。
- CMD 和 PowerShell 包装层应保留子进程的非零退出码；失败分支明确显示未完成及停在哪一阶段。
- 默认输出阶段、计数、耗时和固定错误类别。完整错误、路径清单和状态细节存私有报告；不要把原始 stderr、命令参数或容器环境直接打印出来。
- 一个结果必须区分“预检通过”“变更已应用”“变更后验证通过”“重开后验证通过”。只有目标范围的最终验证才显示全部完成。

## 超时与进度

本地全量哈希所需时间由文件数量、磁盘和杀毒扫描等因素决定，不能复用短 RPC 的 180 秒上限。用分块读取、进度和读取期间的大小／时间／文件身份检查识别工作是否推进；若出现持续无进展，保留记录并诊断，不把无限重试当恢复。

保持 HTTP、模型、数据库和客户端协议的超时独立。不得因为目录扫描慢，统一提高全部子进程或业务请求时限。

桌面退出引起的临时 Git 引用变化只能在准备阶段逐项解释；最终清单仍应包括它们。检查命令依赖 `rg` 时处理其正常的“未找到匹配”退出码，不能把搜索错误与零引用混为一谈。

## 修复后的验证范围

修复外部路径后，继续验证 PATH、cwd、入口参数和退出码；修复第一个聊天后，覆盖原 cwd 是资料目录、已迁移聊天和不同加载状态。不能每次只测刚修的一个点，就把完整未测的后半段再次交给用户。
